本章说明当前版本实际实现了什么，以及背后的主要技术取舍。

## 当前实现

| 部分 | 实现方式 |
| --- | --- |
| Agent | `src/demoAgent.ts` 中的规则：按问题中的关键词分为行动、创意和其他三类，各生成 3 条便签建议 |
| 上下文 | 开启「引用画板」时读取画板标题和文字类元素，关闭后只使用问题本身 |
| 写入 | 建议先以便签预览展示，点击后一次加入画板，位置由代码根据现有内容计算 |
| 停止与恢复 | 生成中可以停止，问题恢复为草稿 |
| 网络 | 不发送任何网络请求，不连接模型 |

工作区数据保存在当前浏览器：

| 数据 | 保存方式 |
| --- | --- |
| 画板、元素、连线与对话 | localStorage |
| 个人资料与画布偏好 | localStorage |
| 未发送的对话草稿 | 按画板保存在 localStorage |
| 撤销历史、生成中状态 | 当前页面内存 |

首次打开、没有有效数据或删除最后一块画板时，创建带示例内容的 **Welcome** 画板；已有有效画板时直接恢复，不重复插入示例。读取时校验数据，写入失败时提示用户。当前不提供跨设备同步，清理站点数据会清除全部内容。

## 主要取舍

| 选择 | 收益 | 代价 |
| --- | --- | --- |
| 纯浏览器模拟，不接入模型 | 无需 Key 或账号，打开即可体验完整交互 | 不展示真实的推理能力 |
| 本地优先存储 | 无需账号，数据留在本机 | 无法跨设备同步，存储空间受浏览器限制 |
| 单 Agent，子 Agent 只读 | 只有一个写入者，结果风格一致 | 资料很多时速度不如并行 |
| 修改先成为提案 | 用户掌控画板，修改可整体撤销 | 每次修改多一步确认 |
| 文件式记忆 | 可读、可编辑、可导出 | 记忆很多时检索能力有限，需要时再增加索引 |
| 按资料选择检索方式 | 画板内容实时，资料检索快 | 需要维护两套检索逻辑 |

## 演进顺序

如果接入真实模型，按以下顺序推进，每一步都可以单独验证：

1. **模型与画板工具**：接入 `canvas_search`、`canvas_read` 和 `canvas_propose`，修改提案沿用现有预览；同时开始记录运行轨迹，建立评测集。
2. **记忆与 Skill**：增加记忆面板和内置 Skill。
3. **知识库与外部工具**：导入资料、接入 MCP，启用细粒度权限和安全策略。

## 验证

自动化测试覆盖数据恢复、画布历史、本地持久化和模拟建议规则；TypeScript 检查与生产构建确保代码可构建。浏览器中验证发送、停止、添加便签和窄屏布局。

网站可以静态托管。Node 启动脚本只用于提供构建文件，没有模型代理或连接接口。
