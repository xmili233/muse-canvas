> **当前演示**：Agent 能否读取画板由「引用画板」开关控制，修改画板需要点击「加入画板」；细粒度权限与安全策略为设计方案。

权限决定 Agent 能做什么，由运行框架在模型之外执行。模型只能提出请求，最终由权限规则决定执行、询问还是拒绝。

## 怎么设计

| 操作 | 默认策略 |
| --- | --- |
| 读取当前画板 | 自动允许，关闭「引用画板」后禁止 |
| 读取其他画板、知识库 | 首次询问，可选择对当前画板记住授权 |
| 修改当前画板 | 生成预览，用户确认后写入 |
| 删除元素 | 在预览中单独标出，逐项确认 |
| 写入记忆 | 用户明确要求时直接写入，Agent 推断时先询问 |
| 访问外部网络 | 每次询问，显示目标地址 |
| 修改其他画板、删除画板 | 不提供对应工具 |

| 模式 | 适用场景 | 行为 |
| --- | --- | --- |
| 讨论 | 只想听建议 | 只读，不生成修改 |
| 协作（默认） | 日常使用 | 按上表执行 |
| 自动整理 | 明确的整理任务 | 修改直接应用并可撤销，删除仍需确认 |

1. **授权绑定到具体资源和操作**：允许读取当前画板，不代表可以读取所有画板；允许新增便签，不代表可以删除内容。
2. **检查在模型之外执行**：每次工具调用先由运行框架按规则判断；被拒绝时向模型返回原因，对话可以继续。
3. **三种协作模式**：用户按任务选择 Agent 的自主程度，不必对每一步逐个确认。
4. **每次修改都能撤销**：Agent 的修改作为一次画板操作进入撤销历史，对话中也保留「撤销这次修改」入口。
5. **阻断数据外泄的组合**：本轮读入不可信内容后，所有对外发送都需要用户确认；Agent 生成的内容不自动加载外部图片和链接。
6. **凭据不进入上下文**：外部服务的令牌由运行框架或代理保管，模型和工具结果中只出现调用结果。

## 为什么这样设计

### 1. 授权绑定到具体资源和操作

按最小权限原则，Agent 只拥有完成当前任务所需的能力。资源和操作分开授权，误操作或被注入时，影响范围也被限制在已授权的部分。

### 2. 检查在模型之外执行

写在提示词里的规则只能降低越界概率，资料中藏着的恶意指令可能让模型忽略它们。研究提示词注入防护的论文指出，启发式的防护手段本质上是脆弱的，可靠的做法是从系统结构上限制 Agent 的能力。代码执行的检查不受模型输出影响。

### 3. 三种协作模式

每一步都要求确认，用户很快会不看内容直接点「允许」，确认失去意义。按任务选择模式，用户只需决定一次，需要谨慎的操作（例如删除）仍然单独确认。

### 4. 每次修改都能撤销

撤销降低了出错的代价，用户才敢放手让 Agent 做更多事。Muse 的画板已有撤销历史，Agent 的修改只需作为一次普通的画板操作写入。

### 5. 阻断数据外泄的组合

Simon Willison 提出的「致命三要素」：Agent 同时能接触私有数据、读到不可信内容、向外发送数据时，攻击者就可以通过注入的指令窃取数据；去掉其中任意一项，这条路径就被切断。

| 要素 | Muse 中的来源 | 控制方式 |
| --- | --- | --- |
| 私有数据 | 画板、记忆、知识库 | 按资源授权 |
| 不可信内容 | 网页、导入的文件、第三方 Skill | 标明来源，只作为数据使用 |
| 对外发送 | 网络工具、外部图片和链接 | 读入不可信内容后，一律需要确认 |

外部图片看似无害，但图片地址可以携带数据，浏览器加载图片时数据就被发送出去，所以不自动加载。

### 6. 凭据不进入上下文

Anthropic 在 Managed Agents 中把令牌放在模型生成的代码接触不到的位置，由代理代为调用外部服务。看不到的凭据，注入的指令也无法窃取。
